# Wayne's brain — one source, three channels

Wayne answers on three surfaces, and all three are **generated from the same
source**: `content/playbook/` in this repo (facts in `facts.yaml` +
`facts-generated.yaml`, per-intent guidance in `intents/*.md`, tone in
`voice-guide.md`, rules in `compliance.md`).

| Channel | Lives in | Regenerated by |
|---|---|---|
| **Web chat** (partyondelivery.com widget) | `src/prompts/reginald.md` (the `PLAYBOOK:BEGIN/END` block) | `npx tsx scripts/playbook/build-chat-prompt.ts` (this repo) |
| **Voice** (Retell agent on (737) 371-9700) | the Retell agent's prompt | `npx tsx scripts/ingest-playbook.ts --voice-push` (partyon-crm repo) |
| **SMS** (CRM auto-replies on the same number) | CRM `sms_agents` row | `npx tsx scripts/ingest-playbook.ts` (partyon-crm repo) |

## To change what Wayne knows or says

1. **Edit the playbook** — a fact goes in `content/playbook/facts.yaml`
   (`status: verified`, and it must be true — every channel will state it);
   how to handle a kind of question goes in the intent card's `## Chat`,
   `## Voice`, or `## SMS` section.

2. **Regenerate web chat** (this repo, same PR as the edit — CI fails otherwise):

   ```bash
   npx tsx scripts/playbook/build-chat-prompt.ts
   ```

   Commit the regenerated `reginald.md` together with the playbook edit.
   The `playbook-lint` test enforces this on every PR.

3. **Push voice** (from the partyon-crm repo, after the playbook edit is merged):

   ```bash
   source apps/web/.env.local && npx tsx scripts/ingest-playbook.ts --voice-push
   ```

   Composes the voice prompt and publishes it to the live Retell agent
   (use `--voice-prompt` first to preview). Takes effect on the next call.

4. **Re-ingest SMS** (from the partyon-crm repo) — ⚠️ **read this first**:

   ```bash
   source apps/web/.env.local && npx tsx scripts/ingest-playbook.ts
   ```

   The full ingest **resets the SMS agent's `reply_mode` to `'draft'`** (a
   deliberate safety), which silently takes Wayne's SMS replies offline. After
   re-ingesting, flip `sms_agents.reply_mode` back to `'live'` and send a test
   text to confirm.

## Never hand-edit the generated copies

Editing the `PLAYBOOK:BEGIN/END` block in `reginald.md`, the Retell prompt in
the dashboard, or `sms_agents.knowledge_base` in the CRM feels faster — but the
next regeneration silently overwrites it. That exact drift muzzled a channel
once already (2026-09: a fact was patched into voice + SMS by hand and the web
chat missed it). The playbook is the only durable place.

Hand-maintained parts DO exist and are safe to edit directly:
- `reginald.md` **outside** the markers (chat persona, mode behaviors)
- the voice-specific header/footer rules — but those live in
  `composeVoiceSystemPrompt` in partyon-crm's `scripts/ingest-playbook.ts`,
  not in the Retell dashboard
